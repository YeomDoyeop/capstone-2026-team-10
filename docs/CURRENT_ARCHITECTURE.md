# 현재 아키텍처 기준

이 문서는 모듈 분리 후 AVE가 현재 따라야 하는 책임과 데이터 경계를 정리한 공통 기준입니다. 전체 처리 흐름, 분석 단계, 저장 대상의 상위 원칙은 [SYSTEM_GUIDELINES.md](SYSTEM_GUIDELINES.md)를 따르며, 이 문서는 현재 구현된 범위와 구체적인 운영 제약을 정합니다. 코드와 계약이 달라지면 실제 코드에 맞춰 이 문서를 함께 갱신합니다.

## 모듈 책임

| 모듈 | 책임 |
| --- | --- |
| `ave-client` | Windows 로컬 서버·트레이·웹 UI, yt-dlp와 FFmpeg를 이용한 수집·분석·자막·렌더링 |
| `ave-server` | 인증, 모든 원격 API의 요청 처리와 결과 반환, 작업 이력·분석 데이터, LLM 및 원격 STT 중계 |
| `ave-whisper-api` | GPU 환경의 음성 전사 API |
| `ave-dist` | PyInstaller 기반 Windows x64 포터블 앱, 외부 바이너리 업데이터와 배포 산출물 관리 |

## 통신 방식

작업 시작·취소·선택 저장·heartbeat와 LLM·RunPod Whisper 호출은 REST API를 사용한다. 장시간 작업의 상태 전달만 SSE를 사용한다. 브라우저 UI는 로컬 클라이언트의 편집 작업 SSE를 구독하고, 로컬 클라이언트는 AVE Server의 Whisper SSE를 구독한다. SSE 연결이 끊겨도 작업 상태·lease·취소는 서버의 일시적 실행 제어 저장소와 REST API를 기준으로 처리한다.

## 데이터 경계

Gemini 3.5 Flash-Lite와 DeepSeek-V4-Flash의 LLM Temperature는 구조화 출력의 안정성을 높이면서 제한적인 재시도 다양성을 유지하도록 `0.1`로 고정합니다.

원본 영상, 렌더링 결과 영상, 로컬 작업 파일과 경로는 클라이언트 PC에만 남깁니다. 서버와 메인 DB에는 **렌더링 성공 뒤에만** 현재 서버 API 계약이 받는 스크립트·구간 분석값·추천·선택 정보와 최소 완료 이력을 저장합니다. 로컬 경로와 진행 상태는 저장하지 않습니다.

2단계 다음에는 4단계 UI로 바로 이동한다. 4-1에서 스크립트 소스와 챕터 분할 방식을 선택하고 문장을 확인한다. 사용자가 **분할**을 누르면 챕터·섹션 분할과 모든 분석 점수를 한 작업에서 계산한다. 4-2는 4-3과 같은 점수 화면을 사용하지만 선택을 잠그고 목표 길이만 수정할 수 있다. **다음**을 누르면 보존된 분할·점수 체크포인트를 사용해 챕터 내 필수 관계 링크만 판별하고 4-3의 선택 가능한 결과로 전환한다. 모든 LLM 요청·응답의 ID는 정수형만 허용한다. 섹션 중요도는 챕터별 summary와 섹션 `[{"id","text"}]` 배열을 전달해 같은 정수 ID의 점수를 받는다. 잘못된 JSON 또는 계약 위반은 추측 보정 없이 최대 100회 시도한다. 재시도 소진은 확률적 LLM 오류로 보고 작업을 일시중지한다.

## 현재 지원 대상

현재 지원하는 입력은 길이가 **10분 이상 6시간 미만**인 일반 업로드 YouTube 영상과 라이브 종료 후 다시보기(VOD) 영상입니다. 현재 라이브 스트리밍 중인 영상은 지원하지 않습니다.

* 스크립트 기반 챕터·섹션 구조와 챕터별 중요도
* 타임스탬프 댓글의 목적·관심 강도 LLM 평가와 섹션별 댓글 점수 표시(현재 추천·선택 계산에는 미사용)
* 큰 상위 주제 단위의 챕터와 독립 선택 가능한 최소 의미 단위의 섹션 구조화
* 시간 표본 사이를 선형 보간한 섹션별 최대 히트맵 점수 표시(현재 추천·선택 계산에는 미사용)
* 지역 기준선 대비 급증을 측정한 섹션별 음량·채팅 점수 표시(현재 추천·선택 계산에는 미사용)
* 채팅 원본 수집과 채팅 시각 파일 생성(현재 편집 점수·밀도에는 미사용)
* AI 추천과 사용자가 확정한 최종 챕터 선택

챕터 LLM·섹션 LLM·히트맵·채팅·댓글·음량 점수는 문서화된 가중치의 선형 결합으로 섹션 총점을 만든다. 요약본 선택은 총점이 높은 섹션부터 앵커로 삼아 같은 챕터에서 이해에 필수적인 연결을 고른다. 관계 요청에는 `allowed_ids`를 보내지 않고, 응답은 입력 배열 위치의 원본 시간순 정수 `indexes` 배열만 받는다. 앵커 위치 반환은 허용하며 클라이언트가 인덱스를 실제 섹션 ID로 복원한다. 선택 길이가 목표 시간을 초과하면 탐색을 중단한다.

## 원격 STT

Whisper는 `1.0~2.0` 배속만 허용하고 원본 시간축의 세그먼트와 단어 타임스탬프를 함께 반환합니다. 클라이언트는 공백 제외 30자 이상인 세그먼트를 먼저 0.5초 이상의 단어 간격에서 나누고, 그 조각이 여전히 30자 이상이면 선택한 LLM에 보냅니다. LLM에는 자막용 분할이며 공백 제외 약 30자가 한 줄의 대략적인 분량임을 알리되 목표 개수는 주지 않습니다. LLM은 가독성과 문법·의미 경계를 기준으로 분할 수를 자율 결정하고 경계 단어 인덱스만 반환합니다. 자연스럽게 나누기 어렵다면 빈 `indexes` 배열을 반환할 수 있으며 이때 클라이언트는 원문을 유지합니다.

원격 STT가 필요한 경우 클라이언트는 `yt-data/{video_id}/{video_id}.mp3`의 최고 품질 원본을 16 kHz·모노·64 kbps로 변환해 `yt-edit/{video_id}/{video_id}.whisper.mp3`에 보존합니다. 원본 오디오의 크기·수정 시각, 언어·초기 프롬프트·핫워드·배속, 엔진·정렬 계약으로 만든 설정 해시와 일치하는 WhisperX 원본 전사가 `yt-edit/{video_id}/whisper-cache`에 있으면 새 작업에서도 업로드와 RunPod 호출을 생략하고 재사용합니다. 캐시가 없을 때만 전사용 MP3를 HTTP로 서버에 업로드합니다. RunPod API는 WhisperX `large-v3`로 한 번 전사한 뒤 언어별 CTC 음향 모델로 강제 정렬하며 `engine=whisperx-aligned-word-v1`, `alignment=ctc-forced-alignment-with-words`와 정렬된 세그먼트·단어 시각을 반환합니다. 공유 캐시를 읽을 때도 요청 지문과 이 두 계약 및 비어 있지 않은 세그먼트를 다시 검증합니다. 클라이언트는 공백 제외 30자 이상인 세그먼트를 자막 가독성에 맞춰 자율 분할하도록 LLM에 요청하고, LLM 경계는 이전 단어 `end`와 다음 단어 `start`의 중간값을 앞뒤 자막의 공통 경계로 사용합니다. 독립 분할 요청에는 섹션 점수 평가와 같은 공급자별 병렬 제한을 적용합니다. 원본 세그먼트의 첫 시작과 마지막 종료는 보존하며 짧은 문장은 세그먼트 시각을 그대로 사용합니다. 작업별 최종 결과는 `whisper-transcript.json`에 저장한 뒤 ACK를 보냅니다. 서버는 ACK가 오거나 15분 TTL이 끝나면 서버 측 임시 오디오와 RunPod 작업 ID·lease·결과를 담은 실행 제어 레코드를 삭제합니다. 서버 배포 환경은 애플리케이션 정리에서 누락된 파일을 위해 root crontab으로 매시간 24시간 초과 `/srv/ave-stt/files` 파일도 삭제한다. 이 짧은 보관 창은 SSE 단절 후 결과를 다시 받기 위한 것이며 메인 DB나 영상 보관 이력이 아닙니다. RunPod 작업 ID 전 취소는 `client_job_id` 기준의 짧은 TTL 취소 의도로 전달하며, 서버는 RunPod 호출 전·후 이를 확인합니다. 완료된 분석 결과만 이력으로 저장합니다. FTP와 로컬 Whisper는 사용하지 않습니다.

## 현재 실행 기준

클라이언트의 개발 실행 진입점은 `python -m app`입니다. 이 명령은 로컬 서버, 시스템 트레이, 브라우저 UI를 시작합니다. 편집 작업 ID는 1단계에서 2단계로 전환하며 추가 자료 다운로드를 시작할 때 한 번 확정하고, 이후 Whisper 재수행·분석·렌더링까지 같은 ID를 유지합니다. 클라이언트는 `/bin`의 `yt-dlp.exe`, `ffmpeg.exe`, `ffprobe.exe`를 사용하며 MoviePy와 Python `yt-dlp` 패키지는 런타임 의존성이 아닙니다.

사용자용 클라이언트는 별도 설치 과정이 없는 PyInstaller 기반 Windows x64 포터블 앱으로 배포합니다. pynsist와 설치 프로그램 방식은 사용하지 않습니다. `ave-dist/build.ps1`은 `ave-client`를 읽기 전용 입력으로 사용해 UI와 Python 실행 파일을 자체 `.build`에서 빌드하고, `ave_client.exe`, `ave_updater.exe`, 외부 정적 UI와 안내 문서를 포함한 ZIP을 생성합니다. 클라이언트 실행 파일은 Python 런타임과 빌드 시점의 `.env`를 포함하며, 작업 DB·미디어·로그는 실행 파일이 있는 디렉터리에 생성합니다. 업데이터는 FFmpeg·FFprobe와 yt-dlp만 내려받아 제공처의 SHA-256으로 검증한 뒤 `bin`에 교체하며 `ave_client.exe`는 변경하지 않습니다. 개발 환경의 실행·기능 검증 기준은 계속 `python -m app`입니다.

## 클라이언트 로컬 저장소

로컬 파일은 수명이 아니라 내용이 결정되는 단위를 기준으로 배치한다. 한 영상에서 항상 동일한 원본 자료는 `yt-data/{video_id}`에 두고, 고정된 처리로 생성되어 같은 영상에서 항상 동일한 파생 자료는 `yt-edit/{video_id}`에 둔다. 작업 설정·외부 응답·사용자 선택·실행 결과에 따라 달라질 수 있는 자료는 `yt-edit/{job_id}`에 둔다.

클라이언트는 `db/ave-client.sqlite3`에 완료된 결과 영상의 최소 조회 정보와 최종 선택 계획·챕터 구조만 저장한다. 진행 상태는 SQLite에 저장하지 않는다. `yt-data/{video_id}`에는 yt-dlp 원본(정보·댓글·채팅·자막·캡션)과 별도로 받은 최고 품질 `{video_id}.mp3`를 보관하고, `yt-edit/{video_id}`에는 2단계 파생 자료를 둔다. `yt-edit/{job_id}`에는 Whisper 전사, 분석 스크립트·계획·LLM 응답과 영상별 음량 분석 점을 포함한 체크포인트, 최종 영상과 모든 렌더링 SRT·결합 영상·인코더별 시도 영상·pending 영상을 둔다. LLM 계약 오류로 일시중지된 작업을 재개할 때는 체크포인트의 음량 분석 점을 재사용해 원본 오디오 분석을 반복하지 않는다. 렌더링 임시 산출물은 성공·취소·실패와 관계없이 삭제하지 않는다. 최종 영상과 JSON은 같은 디렉터리의 임시 파일을 완전히 기록한 뒤 `os.replace`로 원자적으로 교체한다. 취소·실패·중단된 작업의 폴더와 파일도 자동 삭제하지 않고 보존하지만, LLM 재시도 소진으로 일시중지된 작업 외에는 자동 복원하지 않는다. 렌더링 성공 작업만 SQLite와 서버 완료 이력에 기록한다.

`{video_id}.mp3`는 yt-dlp의 `bestaudio/best`와 최고 MP3 품질 설정으로 생성하며 `yt-data/{video_id}`에 보존한다. 영상 다운로드 형식은 현행 정책을 유지한다. 향후 음량 분석에는 이 원본을 사용하며, 원격 Whisper 전사에는 원본을 16 kHz·모노·64 kbps로 고정 변환한 metadata의 `{video_id}.whisper.mp3`를 재사용한다. 전사 결과는 언어·프롬프트·hotwords·배속 등 작업 설정과 원격 실행 결과에 따라 달라질 수 있으므로 작업별 경로에 둔다.

## 개발 단계 작업물 원칙

현재는 개발 단계이므로 테스트와 개발 실행으로 생성된 작업물·결과물·로컬 DB의 보존과 이전 형식 호환을 보장하지 않는다. 저장 구조나 계약이 바뀌면 기존 `media/` 작업물을 삭제하고 새 작업을 생성한다. 호환 코드와 마이그레이션은 실제 사용자 데이터의 보존이 필요해지는 배포 단계에서만 검토한다.
