# 현재 아키텍처 기준

이 문서는 모듈 분리 후 AVE가 현재 따라야 하는 책임과 데이터 경계를 정리한 공통 기준입니다. 전체 처리 흐름, 분석 단계, 저장 대상의 상위 원칙은 [SYSTEM_GUIDELINES.md](SYSTEM_GUIDELINES.md)를 따르며, 이 문서는 현재 구현된 범위와 구체적인 운영 제약을 정합니다. 코드와 계약이 달라지면 실제 코드에 맞춰 이 문서를 함께 갱신합니다.

## 모듈 책임

| 모듈 | 책임 |
| --- | --- |
| `ave-client` | Windows 로컬 서버·트레이·웹 UI, yt-dlp와 FFmpeg를 이용한 수집·분석·자막·렌더링 |
| `ave-server` | 인증, 모든 원격 API의 요청 처리와 결과 반환, 작업 이력·분석 데이터, LLM 및 원격 STT 중계 |
| `ave-whisper-api` | GPU 환경의 음성 전사 API |
| `ave-dist` | 향후 배포 전용 모듈. 현재 설치 프로그램 생성은 진행하지 않음 |

## 통신 방식

작업 시작·취소·선택 저장·heartbeat와 LLM·RunPod Whisper 호출은 REST API를 사용한다. 장시간 작업의 상태 전달만 SSE를 사용한다. 브라우저 UI는 로컬 클라이언트의 편집 작업 SSE를 구독하고, 로컬 클라이언트는 AVE Server의 Whisper SSE를 구독한다. SSE 연결이 끊겨도 작업 상태·lease·취소는 서버의 일시적 실행 제어 저장소와 REST API를 기준으로 처리한다.

## 데이터 경계

원본 영상, 렌더링 결과 영상, 로컬 작업 파일과 경로는 클라이언트 PC에만 남깁니다. 서버와 메인 DB에는 **렌더링 성공 뒤에만** 결과 경로 참조와 최종 선택 계획·챕터 구조 같은 최소 완료 이력을 저장합니다. 피드백, 원본 전사문, 전체 후보 원문, 진행 상태는 저장하지 않습니다.

LLM 분석은 시간순 `{"id": n, "text": "..."}` JSONL 전체를 한 번 호출해 챕터(`start_id`, `end_id`, `summary`, 0~1000 정수 `score`)로 분할하고, 각 챕터를 다시 JSONL로 넣어 섹션(`start_id`, `end_id`)으로 분할한다. 섹션 중요도는 챕터별 summary와 섹션 `[{"id","text"}]` 배열을 한 번에 전달해 같은 ID를 포함한 0~1000 정수 `items` 배열만 받으며 이유나 섹션 요약은 받지 않는다. 클라이언트는 ID 타입·범위·순서·연속성·중복·누락·챕터 포함 관계를 검증하고, 잘못된 JSON 또는 계약 위반은 추측 보정 없이 최대 10회 재시도 후 실패시킨다. 독립적인 챕터별 섹션 분할과 점수 평가는 최대 10개씩 병렬 실행하고 실제 완료 단위로 진행률을 갱신한다. 4단계 응답과 UI는 `chapters[].sections[]`만 사용하며, 챕터·섹션의 실제 LLM 점수 배지와 섹션 선택을 표시한다. 공급자와 무관한 `LLMAnalysisService`와 공통 Gateway를 사용한다.

## 현재 지원 대상

현재 지원하는 입력은 길이가 **10분 이상 6시간 미만**인 일반 업로드 YouTube 영상과 라이브 종료 후 다시보기(VOD) 영상입니다. 현재 라이브 스트리밍 중인 영상은 지원하지 않습니다.

* 스크립트 기반 챕터·섹션 구조와 챕터별 중요도
* 댓글·채팅 원본 수집과 채팅 시각 파일 생성(편집 점수·밀도에는 미사용)
* AI 추천과 사용자가 확정한 최종 챕터 선택

## 원격 STT

원격 STT가 필요한 경우에만 클라이언트가 추출한 임시 오디오를 HTTP로 서버에 업로드합니다. 서버는 원격 Whisper API가 접근할 수 있는 제한 시간 URL을 제공하고 전사 결과를 클라이언트에 반환합니다. 클라이언트는 `whisper-transcript.json`을 저장한 뒤 ACK를 보내며, 서버는 ACK가 오거나 15분 TTL이 끝나면 임시 오디오와 RunPod 작업 ID·lease·결과를 담은 실행 제어 레코드를 삭제합니다. 이 짧은 보관 창은 SSE 단절 후 결과를 다시 받기 위한 것이며 메인 DB나 영상 보관 이력이 아닙니다. RunPod 작업 ID 전 취소는 `client_job_id` 기준의 짧은 TTL 취소 의도로 전달하며, 서버는 RunPod 호출 전·후 이를 확인합니다. 완료된 분석 결과만 이력으로 저장합니다. FTP와 로컬 Whisper는 사용하지 않습니다.

## 현재 실행 기준

클라이언트의 개발 실행 진입점은 `python -m app`입니다. 이 명령은 로컬 서버, 시스템 트레이, 브라우저 UI를 시작합니다. 클라이언트는 `/bin`의 `yt-dlp.exe`, `ffmpeg.exe`, `ffprobe.exe`를 사용하며 MoviePy와 Python `yt-dlp` 패키지는 런타임 의존성이 아닙니다.

설치 프로그램과 pynsist 설정은 아직 범위에 포함하지 않습니다.

## 클라이언트 로컬 저장소

클라이언트는 `db/ave-client.sqlite3`에 완료된 결과 영상의 최소 조회 정보와 최종 선택 계획·챕터 구조만 저장한다. 진행 상태, 전사본, 스크립트, 요약, 전체 후보 원문과 LLM 응답 캐시는 저장하지 않는다. `yt-data/{video_id}`에는 yt-dlp 원본(정보·댓글·채팅·자막·캡션)을 보관하고, `yt-edit/{video_id}.metadata`에는 2단계 파생 자료(댓글 타임스탬프·채팅 시간·롤링 캡션·언어별 파싱 스크립트)를 보관한다. 이 두 경로는 재작업을 위해 유지한다. 3단계는 요청에서 지정한 언어의 파싱 스크립트만 읽고, 다른 언어 파일로 대체하지 않으며 yt-dlp 재수집이나 VTT 재파싱을 하지 않는다. `yt-edit/{job_id}`에는 Whisper 전사 결과, 최종 영상, 렌더링 중의 일시 SRT만 둘 수 있으며 취소·실패·재시작 때 폴더와 이력을 삭제한다.

## 개발 단계 작업물 원칙

현재는 개발 단계이므로 테스트와 개발 실행으로 생성된 작업물·결과물·로컬 DB의 보존과 이전 형식 호환을 보장하지 않는다. 저장 구조나 계약이 바뀌면 기존 `media/` 작업물을 삭제하고 새 작업을 생성한다. 호환 코드와 마이그레이션은 실제 사용자 데이터의 보존이 필요해지는 배포 단계에서만 검토한다.
