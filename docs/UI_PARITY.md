# React UI 동등성 점검표

## 기준선과 판정 원칙

분리 이전 기준선은 `951dc62` 커밋의 `static/index.html`, `static/script.js`, `static/style.css`이다. 이 문서는 현재 `ui/src/WorkflowApp.tsx`와 `ui/src/WorkflowApp.css`를 그 기준선에 대조한 결과이다. `구현됨`은 코드 위치와 자동 또는 수동 검증 방법이 있는 경우에만 사용한다.

서버 책임으로 옮겨진 기능은 UI 동작을 가능한 유지하되, 클라이언트의 로컬 파일·비밀값을 서버에 전달하지 않는 현재 경계를 우선한다.

| 영역 | 기준선의 사용자 동작 | 현재 판정 및 구현 근거 | 검증 |
| --- | --- | --- | --- |
| 헤더·인증 | 연결 상태, Google 로그인·로그아웃, 실행 중 로그아웃 잠금 | 구현됨. 세션 이메일, 로그인 상태, 테마 버튼과 작업 중 로그아웃 잠금이 있다. | `test_react_workflow_retains_the_four_stage_ux_contract`, 브라우저 로그인 |
| 테마 | 라이트/다크 전환과 재실행 후 유지 | 구현됨. `ave-theme` 로컬 저장소와 `data-theme`를 사용한다. | 브라우저 새로고침 |
| 단계 전환 | URL 확인→분석→구간 검토→결과의 4단계 전환, 전환 시 영상 정지·상단 이동 | 구현됨. 4단계 상태와 단계 변경 시 모든 영상 정지를 구현했다. 스크롤 이동은 외부 브라우저 자동 검증 대상으로 둔다. | 단계 이동 수동 검수 |

| 실패·로딩 안내 | 메타데이터, 분석, 렌더링, 자막 저장 실패 메시지 | 구현됨. 각 요청의 응답 오류를 `Status`에 표시하고 실패 상태를 강조한다. | 실패 응답 모의 및 브라우저 |
| 반응형 | 좁은 화면에서 헤더, 메타데이터, 선택 화면, 도크 재배치 | 구현됨. 880px·560px CSS 중단점을 둔다. | 560px/880px 브라우저 수동 검수 |

## 의도적으로 제외한 기준선 기능

| 기준선 기능 | 제외 사유 | 현재 대체 흐름 |
| --- | --- | --- |
| 클라이언트 `.env`의 LLM 키 | LLM 비밀값은 서버 책임이다. | 로그인 토큰으로 서버 API를 호출한다. |
| 로컬 Whisper/faster-whisper | Whisper는 원격 서버 책임이다. | 클라이언트가 최고 품질 원본 MP3를 16 kHz·모노·64 kbps로 변환해 metadata에 보존하고 HTTP로 서버에 전송한다. |
| Azure 파일 서버와 FTP | 원본·렌더링 영상과 로컬 경로를 서버로 전송하지 않는다. | 클라이언트의 로컬 media 경로에서만 제공한다. |
| PC 영상 파일 업로드 | 지원 범위는 YouTube URL과 종료된 라이브 다시보기(VOD)이다. | yt-dlp로 로컬에 수집한다. |
| 진행 중 라이브 추적 | 확정된 지원 범위 밖이다. | 종료된 라이브 다시보기만 처리한다. |

## 외부 연동 수동 검수 항목

- 실제 Google OAuth 콜백과 세션 복구
- VM의 AVE 서버 연결 상태에서 메타데이터 조회, 분석, 선택 렌더링, 자막 재생성 전체 흐름
- Windows 로컬 서버 실행 후 트레이 아이콘, 메모리 로그 스트림 기반 독립 클라이언트 로그 GUI 보기, 브라우저 열기. 로그 창만 닫아도 백그라운드 서버와 파일 로깅이 유지되고 재개방 시 최근 로그가 복원되는지 확인. 트레이 종료 시 Tkinter 관련 스레드 예외 없이 진입점 프로세스가 종료되는지 확인
- 실제 YouTube 종료 VOD에서 구간 미리보기 종료 시점과 렌더링 결과 다운로드

## 완료 확인 명령

```powershell
python -m pytest
npm.cmd run build
python -m app
```

위 명령의 성공만으로 외부 OAuth·YouTube·서버 연동까지 자동 검증되지는 않으므로, 위 수동 검수 항목도 확인한다.
